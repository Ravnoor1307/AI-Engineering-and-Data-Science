Theory : Lists vs Arrays & how memory works

Array (C / Java style) :

  • Fixed size - you decide the capacity BEFORE filling it. Adding one more element when it is full needs a whole new array.
  • Homogeneous - every slot must hold the same type.
  • Very fast & very compact - values sit side by side in one memory block.

Python List (dynamic array) :

  • Dynamic - grows and shrinks automatically as you add/remove items. Python reserves a little extra room and reclaims it as needed.
  • Heterogeneous - one list can hold an int, a float, a string, a bool and even another list.
  • A little slower and uses more memory than a raw C array (because of that extra coating).

How a list is actually stored : A list does NOT copy the numbers inside itself. It keeps a contiguous block of references (pointers) to objects that live elsewhere in memory. id(L) is the address of the list, id(L[0]) is the address of the integer object it points to.

Why do we even need lists? - A single integer variable can store only ONE value. Lists let one name manage a whole collection, so you can process 100 students without writing 100 variables.

python
L = [1, 2, 3]
print(id(L))      # ONE unique id for the list object itself
print(id(L[0]))   # the SAME id as id(1) - Python caches small ints

Deep Dive : Lists vs Arrays & memory

  • A list is a collection of references — every item is a pointer to an object stored elsewhere.
  • id() returns an object's unique memory address (in CPython).
  • The list's address and its items' addresses are all different; Python caches small integers, so id(L[0]) matches id(1).
  • Internally a Python list is an array of PyObject* pointers (~8 bytes per pointer).
  • Array (C/Java style): same-type, contiguous, fixed size, fast. List (Python): heterogeneous, dynamic size, flexible.
  • Nested containers are not flattened — a list inside a list stays a separate object.
  • Indexing is O(1), but each item carries object overhead, so lists are slower and heavier than numpy arrays.
  • id(L) stays constant while items are added; the internal pointer array may be resized, but the list object itself keeps its identity.

print(id(L[0]))
print(id(L[1]))
print(id(L[2]))
print(id(1))
print(id(2))
print(id(3))

Theory : Indexing & Slicing

Indexing = grab ONE item by position.

  • Positive index counts from the LEFT starting at 0 : L[0], L[1] ...
  • Negative index counts from the RIGHT starting at -1 : L[-1] is the last item.
  • Stepping out of range raises IndexError: list index out of range.

Slicing = grab a RANGE : L[start : stop : step]

  • start inclusive, stop EXCLUSIVE, step is the jump.
  • Slicing always returns a NEW list - the original is untouched.

Nested lists chain [] : for L = [[1,2],[3,4]], L[1][0] -> 3.

python
L = [1, 2, 3, 4, 5, 6]
L[1:4]       # -> [2, 3, 4]
L[:3]        # from the start -> [1, 2, 3]
L[::2]       # every 2nd -> [1, 3, 5]
L[::-1]      # REVERSE the list -> [6, 5, 4, 3, 2, 1]

Deep Dive : Indexing & slicing lists

  • Positive 0..n-1 | negative -1..-n

  • Slicing: returns new list (shallow copy of refs)
  • Slice on nested → shallow — inner lists still SAME objects
  • Out of range index → IndexError; slice → clamp
  • .copy() == L[:]
  • Negative slice: L[-2:] last two

Theory : append vs extend vs insert

  • append(x) - adds ONE value at the end. The value becomes a single element, even if it is a list.
  • extend(iterable) - takes an iterable and adds each of its items one by one. Strings get split into characters!
  • insert(index, value) - pushes a value at any position, shifting the rest right.

Memory hook : append adds ONE box, extend dumps the contents of the box into the list.

L.extend('delhi')    # -> [..., 'd','e','l','h','i']
L.insert(1, 100)     # -> [1, 100, 2, 3, ...]

Theory : Deleting from a list

Four tools, two mindsets :

By position (index based)

  • del L[i] - delete the item at index i.
  • del L[a:b] - delete a whole slice.
  • del L - delete the VARIABLE itself (using it later -> NameError).

By value (value based)

  • L.remove(value) - deletes the FIRST occurrence. If the value is absent -> ValueError.
  • L.pop() - removes AND returns the last item (like a stack / LIFO).
  • L.pop(i) - removes AND returns the item at index i.
  • L.clear() - empties the whole list -> [].

pop() gives you the value back, del and remove do not.

python
L = [1,2,3,4,5]
del L[-1]        # [1,2,3,4]
L.pop()          # 4  (and L becomes [1,2,3])
L.remove(2)      # [1,3]
L.clear()        # []

List Comprehension

List Comprehension provides a concise way of creating lists.

The pattern reads: build a new list by evaluating expression for every item drawn from iterable, keeping only those items that pass the optional condition.

Advantages of List Comprehension

  • More time-efficient and space-efficient than equivalent for loops (the loop runs inside C).
  • Require fewer lines of code — a 3-line loop collapses into one readable line.
  • Transform an iterative statement into a formula-like expression, which is easier to inspect and reason about.

You will use list comprehension constantly in data work — mapping values, filtering rows, flattening matrices — so the next few cells walk through its anatomy carefully.

python
new_list = [expression for item in iterable if condition]

Theory : Comprehension - anatomy & how to read it

The shape : Always THREE parts : the expression you compute, the for that supplies items, and an optional if filter.

Read it like the loop it replaces :

  • the expression sits FIRST (where append() would be)
  • the loop comes second, filters after - exactly the nested order of the original loop.

Stacked ifs = AND. Multiple fors = nested loops : Why prefer it? fewer lines, faster (built-in C loop), and it turns a loop into a formula. Avoid ultra-complex comprehensions - readability wins.

python
newlist = [expression for item in iterable if condition]
python
L = []
for i in range(1, 11):
    if i % 5 == 0:
        L.append(i)
# becomes
L = [i for i in range(1, 11) if i % 5 == 0]

Deep Dive : List comprehension — anatomy

Shape: [expression for item in iterable if condition]

  • Order: for first, then if
  • Nested comp = nested for loops
  • Read it left-to-right as: "for each ... in ..., if ..."
  • Faster & more concise than a loop
  • Memory: builds a full list (use a generator expression (x for x in..) for lazy evaluation)
python
# Add 1 to 10 numbers to a list
L = []

for i in range(1,11):
  L.append(i)

print(L)
python
L = [i for i in range(1,11)]
print(L)

Zip

The zip() function returns a zip object, which is an iterator of tuples where the first item in each passed iterator is paired together, and then the second item in each passed iterator are paired together.

Theory : Higher Order Functions (HOF)

A function that TAKES a function and/or RETURNS a function is a higher-order function.

  • transform does not care WHICH function it receives - it just applies it.
  • square and cube are the same shape, so either plugs in.

The three famous HOFs are coming :

  • map - apply a function to every item.
  • filter - keep only items passing a test.
  • reduce - fold many items into one.

HOFs let you say WHAT to do (transform each item) without writing the loop boilerplate yourself.

python
def square(x): return x**2
def cube(x):   return x**3

def transform(f, L):          # f is a FUNCTION parameter
    out = []
    for i in L:
        out.append(f(i))
    print(out)

Theory : map(function, iterable)

map applies a function to EVERY item of an iterable : map(f, L) = [f(x) for x in L].

Important : map returns a LAZY iterator, not a list. Use list(map(...)) to force it (or loop it). It stops early if the iterable does.

Perfect partner of lambda : the function often has no reason to live beyond this one call, so an inline lambda is ideal.

python
list(map(lambda x: x**2, [1,2,3,4,5]))   # -> [1, 4, 9, 16, 25]

L = [1,2,3,4,5]
list(map(lambda x: 'even' if x%2 == 0 else 'odd', L))  # labels

# map over a list of DICTS - extract one field
users = [{'name':'Rahul','gender':'male'},
         {'name':'Ankita','gender':'female'}]
list(map(lambda u: u['gender'], users))   # -> ['male', 'female']

Deep Dive : map(function, iterable)

  • Applies function to EVERY item
  • Returns map OBJECT (iterator) — wrap in list()
  • Function can be lambda or named
  • Multiple iterables: map(f, a, b) → f(x,y)
  • Like list comprehension — map is the functional twin
  • Lazy — one pass produced on list()
  • Example: map(str, [1,2,3]) → '1','2','3'
  • Use for field extraction, transforms, type conversion

# square the items of a list

Theory : filter(function, iterable)

filter keeps only the items for which the function returns True :

How to read it :

  • The function is a PREDICATE - returns True/False, does not transform.
  • Items that pass stay; items that fail are dropped.
  • Original order is preserved.
  • Returns a lazy iterator -> wrap with list().

map CHANGES every item; filter SELECTS some items. They compose beautifully : filter first, then map.

python
L = [3,4,5,6,7]

Glossary

Array (C / Java style)

- Fixed size - you decide the capacity BEFORE filling it. Adding one more element when it is full needs a whole new array.

Python List (dynamic array)

- **Dynamic** - grows and shrinks automatically as you add/remove items. Python reserves a little extra room and reclaims it as needed.

Heterogeneous

one list can hold an int, a float, a string, a bool and even another list.

How a list is actually stored

A list does NOT copy the numbers inside itself. It keeps a contiguous block of **references (pointers)** to objects that live elsewhere in memory. id(L) is the address of the list, id(L[0]) is the address of the integer object it points to.

By position (index based)

`del L[i]` - delete the item at index i.

By value (value based)

`L.remove(value)` - deletes the FIRST occurrence. If the value is absent -> `ValueError`.

Arithmetic

`+` concatenates two lists -> a NEW list (originals untouched) : `[1,2] + [3,4] = [1,2,3,4]`

Membership

`in` / `not in` -> is a value present? Works at ANY depth for nested lists : `[5,6] in [[5,6],7]` -> True.

Looping

`for i in L` walks the items in order. For `[[[1,2],[3,4]],[[5,6],[7,8]]]`, each `i` is one 2D sub-list.

Equality

`==` compares items one by one in order : `[1,2,3] == [3,2,1]` -> False (order matters).

Advantages of List Comprehension

More time-efficient and space-efficient than equivalent `for` loops (the loop runs inside C).
