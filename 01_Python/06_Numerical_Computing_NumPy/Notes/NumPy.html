Unit Overview

Welcome to Numerical Computing with NumPy! This session is where your Python skills start turning into true data-science skills. So far you have worked with Python lists, which are flexible but slow when dealing with tens of thousands of numbers. NumPy — short for Numerical Python — is the foundational library for scientific computing. It provides the ndarray (n-dimensional array), a homogeneous, fixed-size grid of numbers that lives in one contiguous block of memory. Because of that layout, operations on whole arrays run in compiled C code, often tens of times faster than an equivalent Python loop.

Why does this matter? Nearly every serious Python library used for machine learning and data analysis — pandas, scikit-learn, TensorFlow, PyTorch — is built on top of NumPy's array model. When you load images, tables, or sensor data, the numbers arrive as NumPy arrays. When you train a neural network, the weights are stored and updated inside arrays. Mastering NumPy is therefore not optional for a data scientist; it is the shared language of the field.

In this session you will learn, in order:

  1. What an ndarray is and how it differs from a Python list.
  2. The many ways to create arrays: np.array, np.arange, np.linspace, np.ones, np.zeros, np.random.random, and np.identity.
  3. Array attributes (ndim, shape, size, dtype, itemsize) that tell you everything about the structure of your data.
  4. Changing data types with astype.
  5. Elementwise arithmetic and comparison operations that need no loops.
  6. Universal functions and reductions, including the crucial axis parameter.
  7. Indexing, slicing, and iterating over arrays.
  8. Reshaping, transposing, stacking, and splitting arrays.

A mental model that will serve you well: think of a NumPy array as a grid of numbers with a fixed shape. Operations act on the whole grid at once, and the shape — (rows, columns) or (depth, rows, columns) — defines how you step through the data. Everything else in NumPy is built from that single idea. Let's begin.

Session 13 gave you the building blocks: creating arrays, reading their shape, slicing, and reshaping. This session upgrades you from a NumPy user to a NumPy thinker. The four big ideas you will meet are speed, power indexing, broadcasting, and formulas.

First, speed. A Python loop touches each element through the interpreter, which is slow. A NumPy operation hands a whole array to compiled C code that walks the memory directly, so the same addition can be 50-100 times faster — and leaner in memory, because every element is stored cleanly next to its neighbours. This is why real machine learning loops are almost invisible inside NumPy calls.

Second, power indexing. Plain slicing picks blocks. Fancy indexing picks any scattered positions with an index array, and boolean masking picks exactly the values that satisfy a condition. These two techniques replace entire pages of filter logic with a single line and are the closest thing data scientists have to a SQL WHERE clause.

Third, broadcasting. When two arrays have different shapes, NumPy does not panic — it stretches the smaller one across the larger, provided the dimensions are compatible. Mastering the two broadcasting rules lets you write code for the general case and stop reshaping by hand.

Fourth, formulas. Machine learning is a collection of vectorised equations. The sigmoid, mean-squared-error, and binary cross-entropy functions are each a one-liner once you combine np.exp, np.mean, and elementwise arithmetic. Seeing a neural network as a chain of array formulas turns scary math into plain NumPy.

You will also handle missing data with np.nan, visualise formulas with matplotlib, and build coordinate grids with meshgrid for surface plots. Every idea here is a tool you will reuse in pandas and in every model you train. Let's begin with why NumPy wins on speed.

Core Concepts

NumPy Fundamentals

Numpy Arrays Vs Python Sequences

  • NumPy arrays have a fixed size at creation, unlike Python lists (which can grow dynamically). Changing the size of an ndarray will create a new array and delete the original.

  • The elements in a NumPy array are all required to be of the same data type, and thus will be the same size in memory.

  • NumPy arrays facilitate advanced mathematical and other types of operations on large numbers of data. Typically, such operations are executed more efficiently and with less code than is possible using Python’s built-in sequences.

  • A growing plethora of scientific and mathematical Python-based packages are using NumPy arrays; though these typically support Python-sequence input, they convert such input to NumPy arrays prior to processing, and they often output NumPy arrays.

ones / zeros / random / linspace / identity

  • ones(shape) and zeros(shape) accept a shape tuple and fill every cell with 1 or 0 — perfect for placeholder matrices, masks, and bias initialisation.
  • random.random(shape) produces uniform random floats between 0 and 1; np.random.rand is a similar helper.
  • linspace(start, stop, n) returns exactly n points evenly spaced between start and stop, both included. Use linspace when you know how many points you want; use arange when you know the step size.
  • identity(n) builds the n x n identity matrix with 1s on the main diagonal.
  • All of these builders accept either a single integer (1D) or a shape tuple (N-D).
python
np.ones((3, 4))                # a 3x4 array filled with 1s
np.zeros((3, 4))               # a 3x4 array filled with 0s
np.random.random((3, 4))       # uniform random floats in [0, 1)
np.linspace(-10, 10, 10, dtype=int)   # 10 evenly spaced integers
np.identity(3)                 # 3x3 identity matrix

Why these builders matter

A good NumPy habit is to allocate arrays with a one-line builder instead of filling a Python list with a loop.

  • ones and zeros are the standard way to create blank arrays before filling them. In machine learning you will initialise weight matrices, masks, and bias vectors to zeros all the time.
  • random.random samples uniformly from the interval [0, 1). When you need a normal (Gaussian) distribution instead, reach for np.random.randn; a uniform sample produces a flat histogram, while a normal sample produces the familiar bell curve.
  • linspace is count-based: np.linspace(-10, 10, 10) always gives exactly 10 values, -10 through 10. arange is step-based and end-exclusive: np.arange(-10, 11, 2) gives -10, -8, ..., 10. Choosing the right one depends on whether you think in terms of the number of points or the step size.
  • identity(n) is the matrix that leaves every vector unchanged under multiplication: I @ v == v. It is the multiplicative identity for matrices, the same way 1 is for numbers.
  • Passing dtype=int to linspace truncates the evenly spaced floats to integers, which is exactly what the code cell below demonstrates.

Changing Datatype

What/Why

Variables reference objects in memory. Data types determine operations allowed and behavior.

Semantics

Python is dynamically typed. Assignment binds names to objects; mutability matters.

Common mistakes

Confusing assignment vs comparison, mutability side effects.

  • astype(type) converts an array to a new dtype and returns a new array; the original remains untouched.
  • Float to int truncates towards zero, so 3.9 becomes 3.
  • Int to float widens the type so fractional values can be represented.
  • Why bother? Lower-precision types such as int32 or float32 use half the memory of their 64-bit counterparts. Downcasting large datasets saves memory, and aligning the dtype of model inputs avoids cryptic errors later.
python
array.astype(np.int32)   # returns a NEW array in the new type

Deep Dive : Changing datatype — astype

  • memory: float64 takes double int32
  • usage: downcast dataset for efficiency
  • object → numeric conversions reserved
  • errors: 'raise'/'ignore'
  • monetary precision: keep float64
  • ML: model input dtype alignment
  • Check result: .dtype / .nbytes

Iterating arrays

  • Iterating an ndarray with a plain for loop walks the outermost axis.
  • A 2D array yields rows; a 3D array yields 2D slabs; only a 1D array yields scalars.
  • np.nditer(a) flattens the traversal so you visit every element one by one.
  • In real data pipelines, prefer vectorised functions over loops — but know how iteration works so you can inspect arrays during debugging.
python

for i in a2:            # 2D — yields each row
for i in a3:            # 3D — yields each 2D block
for i in np.nditer(a3): # yields every scalar element

Numpy vs Python lists — speed
  • NumPy is C/CPU optimized — ~50-100x faster than a pure loop
  • This code is measured with time.time()
  • A vectorized operation runs in a single pass, no loop involved
  • In data science, this is exactly what makes the difference on large arrays
python
import numpy as np
import time

# Python list addition (loop)
c = [x + y for x, y in zip(a, b)]

# Numpy vectorized
a = np.arange(10000000)
c = a + b

Deep Dive : Speed — vectorization wins

  • Vectorized ops run at C speed (SIMD + no Python loop)
  • Same operation: numpy ~50-100x faster than Python list loop
  • Reason: tight C loop + contiguous memory
  • Python per-element creates interpreter overhead
  • Approx 3.26s vs 0.06s (~54x)
  • CPU: numpy uses optimized BLAS/LAPACK in many ops
  • Rule: never element-loop when vector op exists
  • This scale: 10M element addition instant
  • ML data millions row — numpy is the backbone
python
# speed
# list
a = [i for i in range(10000000)]
b = [i for i in range(10000000,20000000)]

c = []
import time 

start = time.time()
for i in range(len(a)):
  c.append(a[i] + b[i])
print(time.time()-start)
python
# numpy
import numpy as np
a = np.arange(10000000)
b = np.arange(10000000,20000000)

start = time.time()
c = a + b
print(time.time()-start)

Broadcasting

The term broadcasting describes how NumPy treats arrays with different shapes during arithmetic operations.

The smaller array is “broadcast” across the larger array so that they have compatible shapes.

Broadcasting — same shape

  • Same shape → direct elementwise, no magic involved
  • Broadcasting comes into play when the shapes DIFFER
python
a = np.arange(6).reshape(2, 3)     # (2,3)
b = np.arange(6, 12).reshape(2, 3) # (2,3)
a + b   # elementwise direct

Deep Dive : Broadcasting — same shape

  • Broadcasting = elementwise ops between compatible shapes
  • Same shape → direct elementwise, no copy
  • Compares shape dim-by-dim
  • Rule 1: same dims → fine
  • a + b → c[i,j] = a[i,j]+b[i,j]
  • Vectorized — fast
  • Diff shape needs broadcast rule (covered later)
  • Matrices: shapes equal or 1 / missing
  • Alignment: trailing dims first
  • Works for + - * / ** etc.
  • numba-vectorized intuitive
python
# same shape
a = np.arange(6).reshape(2,3)
b = np.arange(6,12).reshape(2,3)

print(a)
print(b)

print(a+b)
python
a = np.arange(6).reshape(2,3)
b = np.arange(6,12).reshape(2,3)
a + b        # elementwise — shapes match directly

Broadcasting — different shapes

  • When shapes differ, NumPy stretches the smaller array so both end up compatible.
  • Here b has shape (1, 3); its single row is replicated until b behaves like (2, 3) before the addition.
  • No loops are written — the operation stays fully vectorised.
  • Stretching only works when every dimension of the two arrays matches or is 1; the formal rules follow below.
python
a = np.arange(6).reshape(2, 3)     # (2, 3)
b = np.arange(3).reshape(1, 3)     # (1, 3)
a + b   # b is stretched to (2, 3) and added elementwise

Deep Dive : Broadcasting — different shapes

  • a (2,3) + b (3,) → b broadcast to (2,3)
  • Trailing dimensions align; dims of size 1 stretch
  • Rule 2: dims either equal or one of them is 1
  • Rules summary:
    1. align trailing dims
    2. minus-minus: equal | 1 stretches | missing treated 1
    3. result shape = max dims
  • Examples:
    • (3,4) + (4,) ✓
    • (3,4) + (1,4) ✓
    • (3,1)+(1,4) → (3,4) ✓
    • (3,4)+(4,3) ✗ mismatch
    • (4,4)+(2,2) ✗
  • Scalar broadcast: (2,3)+5 → all
  • Concept: no explicit loops — implicit replication
  • Widely used w/ mean subtract, scaling, neural nets bias
python
# diff shape
a = np.arange(6).reshape(2,3)
b = np.arange(3).reshape(1,3)

print(a)
print(b)

print(a+b)
python
a = np.arange(6).reshape(2,3)   # (2,3)
b = np.arange(3).reshape(3)     # (3,)
a + b        # b stretches along rows → each row + b

Broadcasting Rules

1. Make the two arrays have the same number of dimensions.

  • If the numbers of dimensions of the two arrays are different, add new dimensions with size 1 to the head of the array with the smaller dimension.

2. Make each dimension of the two arrays the same size.

  • If the sizes of each dimension of the two arrays do not match, dimensions with size 1 are stretched to the size of the other array.
  • If there is a dimension whose size is not 1 in either of the two arrays, it cannot be broadcasted, and an error is raised.

The closing eight — swapaxes, uniform, count_nonzero, tile, repeat, allclose

The final stubs round out the collection.

  • np.swapaxes(a, i, j) exchanges two axes of an array; for 2D input it is the same as transposing, but it works on any pair of axes in higher dimensions.
  • np.random.uniform(low, high, size) draws continuous random values evenly spread between low and high — useful when you need a custom range instead of [0, 1).
  • np.count_nonzero(a) counts how many elements are non-zero, or equivalently how many are True in a boolean mask — the fast way to tally matches.
  • np.tile(a, reps) repeats the whole array to build a bigger block.
  • np.repeat(a, n) repeats each element n times before moving on — the distinction from tile is worth memorising.
  • np.allclose(a, b) returns True when two arrays are equal within a small tolerance; because floats rarely match exactly after computation, allclose is the community-standard comparison for test assertions.

Run each stub, predict the output, then check. Being able to choose between these six at the right moment is a strong sign the toolkit has sunk in.
