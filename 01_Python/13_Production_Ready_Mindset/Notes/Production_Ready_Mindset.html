🧼 01 — Clean/Readable Code: The 6 Laws of Straight-Forward Style! ✍️

Topic 14.01 | ProductionReadyMindset — Part 1 of 4

🌍 Hook: You wrote code that today's-genius understood; 3 MONTHS later you read it yourself and say "which MADMAN wrote this?!" 😂 Code is not just for the compiler — it's for HUMANS! In interviews/production/quick-fixes the most VALUABLE skill = READABLE code!

📖 The 6 Laws (rules-of-thumb!):

  1. Names = the story — say WHOSE, WHAT (a, x1 ❌ → student_avg ✅)
  2. Small functions — one function, one answer (a ~20-line ceiling!)
  3. DRY — copy-paste = the clone-army of future bugs 🪳
  4. Magic-numbers = ghosts — 0.9?? put it in constants!
  5. Comments = WHY, code = WHAT — i += 1 # i badhata 😑 worthless!
  6. Dead-code = delete — git-history keeps the memory — scrap it! 🗑️

🔍 WHY: bug-hunting 10x faster, adding features 3x faster, and the team loves you! ♥

🛩️ 01 — Logging & Monitoring Mindset: The Black-Box Mentality!

On a production-server too, your app-crash is the same thing: the boss asks "when did it come, what happened?" — only logs can tell! print = writing a note on paper and throwing it in the wind ✉️💨 — a logger = the black-box!

📖 MINDSET-First (you learned the syntax in §11, now the THINKING):

Thought Direct meaning
WHICH level? DEBUG=developer-diary · INFO=work-flowing 🟢 · WARNING=heavy-breathing! 🟡 · ERROR=fell! 🔴 · CRITICAL=fire-alarm! 🚨
WHAT to log? events + decisions + numbers (rows→parse→avg!); clues for future fixes
WHAT NOT to log? PASSWORDS/tokens/cards — always mask/no-store ⚠️
Monitoring = health-checks + dashboards ON TOP of logs (the alert-pyramid!)

STATUS_OK = "OK"            # kabhi "OKAY"/"ok" nahi — ek-hi shabd! 🎯

def parse_sensor_line(line: str):
    """"s1|42.5|OK" → ("s1", 42.5)  |  wahi-line status OK nahi → None"""
    parts = line.split("|")
    if len(parts) < 3 or parts[2] != STATUS_OK:
        return None
    return parts[0], float(parts[1])

def average_of(keepers: list) -> float:
    return round(sum(v for _, v in keepers) / len(keepers), 1) if keepers else 0.0

def sensor_sift(lines: list[str]):
    keepers = [k for k in (parse_sensor_line(l) for l in lines) if k]
    return keepers, average_of(keepers)

res2, avg2 = sensor_sift(RAW)
print("after-out :", res2, "| avg:", avg2)
assert (res, avg) == (res2, avg2)     # SAME outputs, NAYI readability! 🎉
print("✅ same-answer proof — parlour seva success!")
# Expected OUTPUT:
# after-out : [('s1', 42.5), ('s3', 60.0)] | avg: 51.2

Step 1+2 — README-Glimpse + TREE + ENTRY-Find 🔍

How do you find the entry point? LINE-GREP for the __main__-guard (the craftsman's pattern!)

Exceptions

Handle errors gracefully with try/except/else/finally. Avoid bare except; catch specific exceptions.

python
print("README peeks:", (repo / "README.md").read_text().splitlines()[1])

def find_entry_guards(root: Path):
    hits = []
    for py in sorted(root.glob("*.py")):
        for i, line in enumerate(py.read_text().splitlines(), 1):
            if '__name__' in line:
                hits.append(f"{py.name}:{i}: {line.strip()}")
    return hits

print("\n__main__-guards scan:", find_entry_guards(repo))
print("→ ENTRY = cli.py (fit line 6-8 guard!) 🎯")
